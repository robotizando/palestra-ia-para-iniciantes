Embedding: cada token ganha um endereço

1. O número vira uma lista de números

“bolo” → 4821 → [0,9; 0,7; …]

Essa lista é aprendida no treino. Palavras que aparecem em frases parecidas ficam perto no mapa.

2. Parecido = perto (cosseno)

cos(a, b) = (a · b) / (|a| |b|)

bolo × torta = 1,28 / (1,14 · 1,13) ≈ 0,99
bolo × carro = 0,12 / (1,14 · 0,85) ≈ 0,12

3. Dá até para fazer conta com sentido

rei − homem + mulher ≈ rainha

Opcional, para quem quiser ir além do token. Depois de virar número (o ID do dicionário), cada token vira uma lista de números, o embedding. No mapa do slide cada palavra tem só 2 números para caber no desenho; nos modelos de verdade são centenas ou milhares por token. Essa lista não é escrita à mão: é aprendida no treino, e palavras usadas em frases parecidas acabam perto umas das outras (comidas num canto, veículos em outro). Para medir se duas palavras são parecidas, usa-se o cosseno do ângulo entre as listas: perto de 1 é muito parecido, perto de 0 não tem nada a ver. Conta do exemplo: bolo = (0,9; 0,7) e torta = (0,8; 0,8): 0,9·0,8 + 0,7·0,8 = 1,28; os tamanhos são 1,14 e 1,13; cosseno ≈ 0,99. Bolo e carro = (0,6; −0,6): 0,54 − 0,42 = 0,12; cosseno ≈ 0,12. A seta de homem para mulher é igual à de rei para rainha, por isso rei − homem + mulher cai em rainha (no mapa: (−0,3; 0,5) − (−0,8; 0,2) + (−0,8; −0,2) = (−0,3; 0,1)). Nos modelos reais isso funciona de forma aproximada, não exata. Ligação com parâmetros: um dicionário de 100 mil tokens com 4.096 números cada já são uns 410 milhões de parâmetros, só nessa tabela. Uso no dia a dia: é assim que os Projetos do Claude e as buscas "por significado" acham o trecho certo de um documento, mesmo sem a palavra exata.
